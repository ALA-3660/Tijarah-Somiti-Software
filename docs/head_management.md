# Phase 4.3 — Income & Expense Head Classification & Integration Documentation

## ১. ভূমিকা ও ডোমেন বিভাজন (Domain Separation)

তিজারাহ সমিতি সফটওয়্যারে ৩-মাত্রিক ইসলামিক অ্যাকাউন্টিং কাঠামোর প্রথম স্তম্ভ হলো **খাত শ্রেণি ও ব্যবস্থাপনা (Head Classification & Management — Phase 4.3)**।

### মৌলিক নীতিমালা: **`Head ≠ Fund ≠ Account`**
* **খাত (Head - কেন?):** টাকা কেন এসেছে বা কেন খরচ হয়েছে (অর্থনৈতিক কারণ/শ্রেণি)। যেমন: নতুন সদস্য ভর্তি ফি, মাসিক চাঁদা, অফিস ভাড়া, কর্মচারীদের বেতন। (খাত কোনো ব্যালেন্স বা টাকা ধারণ করে না)।
* **তহবিল (Fund - কোন উদ্দেশ্যে?):** কোন সুনির্দিষ্ট উদ্দেশ্য বা বিধিবদ্ধ শ্রেণির অধীনে অর্থ বরাদ্দ/সংরক্ষিত রাখা হয়েছে। যেমন: সাধারণ তহবিল, শেয়ার মূলধন তহবিল, উন্নয়ন তহবিল।
* **হিসাব (Account - কোথায়?):** অর্থ বাস্তবিকভাবে কোথায় গচ্ছিত আছে। যেমন: ক্যাশ ইন হ্যান্ড (নগদ বাক্স), ইসলামী ব্যাংক সঞ্চয়ী হিসাব, আল-আরাফাহ ব্যাংক চলতি হিসাব।

> **সতর্কবার্তা:** Phase 4.3-এ কোনো Financial Transaction, Ledger বা Account Management অন্তর্ভুক্ত নয়। এটি সম্পূর্ণ মাস্টার ডেটা ক্লাসিফিকেশন ও ক্যাটালগ লেয়ার।

## ২. ডোমেন মডেল ও ফিল্ড স্পেসিফিকেশন (Domain Model)

### `Head` Entity Structure
| ফিল্ডের নাম | টাইপ | বাধ্যতামূলক? | অপরিবর্তনীয়? | বিবরণ |
|---|---|---|---|---|
| `id` | UUID / String | হ্যাঁ | হ্যাঁ | খাতের বৈশ্বিক ইউনিক আইডেন্টিফায়ার |
| `organizationId` | UUID / String | হ্যাঁ | হ্যাঁ | সমিতি আইসোলেশন স্কোপ (Multi-tenant) |
| `headCode` | String | হ্যাঁ | হ্যাঁ | ইউনিক কোড (যেমন: `INC-001`, `EXP-001-01`), সৃষ্টির পর অপরিবর্তনীয় |
| `name` | String | হ্যাঁ | না | খাতের নাম (বাংলা-ফার্স্ট, Unicode NFC Normalized) |
| `description` | String | না | না | বিস্তারিত বিবরণ |
| `headType` | Enum (`income`, `expense`) | হ্যাঁ | হ্যাঁ | খাতের অর্থনৈতিক প্রকৃতি (আয় বা ব্যয়, সৃষ্টির পর অপরিবর্তনীয়) |
| `parentId` | UUID / String / null | না | হ্যাঁ | প্রধান খাতের আইডি (উপ-খাতের ক্ষেত্রে বাধ্যতামূলক, প্রধান খাতে `null`) |
| `level` | Integer (`1`, `2`) | হ্যাঁ | হ্যাঁ | লেভেল ১ = Main Head, লেভেল ২ = Sub Head |
| `isSystemDefined` | Boolean | হ্যাঁ | হ্যাঁ | সিস্টেম নির্ধারিত টেমপ্লেট (`true`) নাকি কাস্টম (`false`) |
| `isActive` | Boolean | হ্যাঁ | না | ব্যবহারের জন্য সক্রিয় কি না |
| `status` | Enum (`active`, `inactive`, `archived`) | হ্যাঁ | না | লাইফসাইকেল অবস্থা |
| `sortOrder` | Integer | হ্যাঁ | না | প্রদর্শন ক্রমানুসার |
| `createdAt` | ISO-8601 String | হ্যাঁ | হ্যাঁ | তৈরির টাইমস্ট্যাম্প |
| `updatedAt` | ISO-8601 String | হ্যাঁ | না | সর্বশেষ আপডেটের টাইমস্ট্যাম্প |
| `createdBy` | String | না | হ্যাঁ | পরিচালনাকারীর নাম/আইডি |
| `updatedBy` | String | না | না | সর্বশেষ সম্পাদনাকারীর নাম/আইডি |

## ৩. হায়ারার্কি ও ভ্যালিডেশন পলিসি (Hierarchy & Classification Rules)

1. **দ্বি-স্তরীয় সীমাবদ্ধতা (2-Level Hierarchy):**
   * **Level 1 (Main Head):** `parentId = null`
   * **Level 2 (Sub Head):** `parentId = Valid Active Main Head ID`
   * ৩য় বা তদূর্ধ্ব জটিল রিকার্সিভ হায়ারার্কি সম্পূর্ণ অবরুদ্ধ।

2. **টাইপ কনসিস্টেন্সি ও কঠোর ইমিউটেবিলিটি (Type Consistency & Immutability):**
   * Income Sub Head শুধুমাত্র Income Main Head-এর অধীনে যুক্ত হতে পারবে।
   * Expense Sub Head শুধুমাত্র Expense Main Head-এর অধীনে যুক্ত হতে পারবে।
   * Income এবং Expense মিশ্রণ বা রূপান্তর (Conversion) ব্যাকএন্ড ও ফ্রন্টএন্ডে অবরুদ্ধ।

3. **ইউনিকোড এনএফসি নরম্যালাইজড ডুপ্লিকেট চেকিং:**
   * খাতের নামের ডুপ্লিকেট রোধে `normalizeText = text.normalize('NFC').trim().toLowerCase()` প্রয়োগ করা হয়।
   * একই মূল খাতের অধীনে সমগোত্রীয় উপ-খাতের নাম ইউনিক হতে হবে।

4. **ক্রস-অর্গানাইজেশন প্রতিরোধ (Cross-Org Protection):**
   * কোনো সাব-হেড অন্য কোনো সমিতির মূল খাতের অধীনে যুক্ত হতে পারবে না।

5. **সার্কুলার ও স্ব-প্যারেন্ট প্রতিরোধ (No Circular or Self Reference):**
   * একটি খাত নিজের প্যারেন্ট হতে পারবে না (`id !== parentId`)।

6. **নিরাপদ লাইফসাইকেল ও পেরেন্ট ডিপেন্ডেন্সি (Safe Lifecycle):**
   * জিরো হার্ড ডিলিট (Zero Hard Delete) নীতি কার্যকর।
   * সক্রিয় সাব-হেড বিদ্যমান থাকলে মূল খাতকে সরাসরি `inactive` বা `archived` করা যাবে না।

## ৫. অপরিবর্তনীয় অডিট লগ (Immutable Audit Trail)

নিম্নোক্ত প্রতিটি ইভেন্টের ক্ষেত্রে অডিট রেকর্ড বাধ্যতামূলক:
* `HEAD_CREATED`: নতুন মূল খাত বা সাব-হেড তৈরি।
* `HEAD_UPDATED`: খাতের নাম, বিবরণ বা ক্রম সংশোধন (কোড, টাইপ ও আইডি অপরিবর্তিত থাকে)।
* `HEAD_ACTIVATED`: নিষ্ক্রিয় খাত পুনরায় সক্রিয়করণ।
* `HEAD_DEACTIVATED`: খাতের কার্যক্রম স্থগিত/নিষ্ক্রিয়করণ (কারণসহ)।
* `HEAD_ARCHIVED`: অপ্রচলিত খাত স্থায়ী সংরক্ষণাগারে স্থানান্তর।
