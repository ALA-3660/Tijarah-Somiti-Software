## ১. মূল আর্কিটেকচারাল নীতিমালা (Core Architectural Principles)

### ক. Member ≠ User (সুস্পষ্ট ডোমেইন পৃথকীকরণ)
* **Member (সমিতির সদস্য):**
  - সমবায় বা সমিতির সাধারণ বা আজীবন সদস্য (আইনি ও সামাজিক সত্ত্বা)।
  - সদস্য হওয়ার সাথে সাথে সফটওয়্যার লগইন অ্যাকাউন্ট থাকা বাধ্যতামূলক নয়।
  - সদস্যের রয়েছে নিজস্ব প্রোফাইল, সদস্য কোড (`MEM-000001`), জাতীয় পরিচয়পত্র (NID), যোগাযোগের ঠিকানা এবং সদস্যপদ স্থিতি।
  - ভবিষ্যতে কোনো সদস্য সফটওয়্যারে লগইন করার প্রয়োজন হলে তার সাথে একটি ঐচ্ছিক `userId` রেফারেন্স যুক্ত হতে পারবে।
* **User (সফটওয়্যার ব্যবহারকারী):**
  - সফটওয়্যারে লগইন করার আইডেন্টিটি ও প্রশাসনিক ভূমিকা (`Role`) যুক্ত অ্যাকাউন্ট (`USR-000001`)।
  - সদস্য ডিলিট বা স্ট্যাটাস পরিবর্তনে ইউজারের কোনো ক্ষতি হয় না, একইভাবে ইউজার অ্যাকাউন্টে কোনো পরিবর্তন সদস্য সত্ত্বাকে প্রভাবিত করে না।

### খ. Multi-tenant Organization Isolation (প্রতিষ্ঠানভিত্তিক ডাটা আইসোলেশন)
* প্রতিটি সদস্য বাধ্যতামূলকভাবে একটি নির্দিষ্ট `organizationId`-এর অধীনে আবদ্ধ।
* এক প্রতিষ্ঠানের সদস্য তালিকা, প্রোফাইল, সার্চ বা ফিল্টার অন্য কোনো প্রতিষ্ঠান দেখতে বা পরিচালনা করতে পারবে না।

### গ. হার্ড-ডিলিট সম্পূর্ণ নিষিদ্ধ (No Hard Deletion)
* সদস্যপদ সংক্রান্ত কোনো রেকর্ড ডাটাবেজ থেকে স্থায়ীভাবে মুছে ফেলা (`DELETE`) সম্পূর্ণ নিষিদ্ধ।
* সদস্যপদ সমাপ্তি, স্থানান্তর বা পদত্যাগের ক্ষেত্রে উপযুক্ত কারণসহ লাইফসাইকেল ট্রানজিশন (`archived` বা `inactive`) প্রয়োগ করতে হবে।

### ঘ. অপরিবর্তনীয় ফিল্ডসমূহ (Immutable Fields Enforcement)
* `id` (স্থায়ী UUID)
* `organizationId` (প্রতিষ্ঠানের রেফারেন্স)
* `memberCode` (অনন্য সদস্য কোড যেমন: `MEM-000001`)
* `createdAt` (তৈরির সময়)
* `createdBy` (তৈরি কারক)

## ৩. সদস্যপদ লাইফসাইকেল (Member Status Lifecycle)

```
       ┌───────────────┐
       │    Active     │ ◄──────────┐
       │   (সক্রিয়)    │            │
       └───┬───────┬───┘            │
           │       │                │
           ▼       ▼                │
┌──────────────┐ ┌──────────────┐   │
│   Inactive   │ │  Suspended   ├───┘
│  (নিষ্ক্রিয়)  │ │   (স্থগিত)   │
└──────┬───────┘ └──────┬───────┘
       │                │
       └───────┬────────┘
               ▼
       ┌──────────────┐
       │   Archived   │
       │ (আর্কাইভকৃত)  │
       └──────────────┘
```

1. **Active (সক্রিয়):** নিয়মিত সদস্য, সাধারণ সভায় ভোট ও সমিতির কার্যক্রমে অংশগ্রহণের যোগ্য।
2. **Inactive (নিষ্ক্রিয়):** সাময়িকভাবে অনুপস্থিত বা আবেদনে স্থগিত।
3. **Suspended (স্থগিত):** শৃঙ্খলাভঙ্গ বা প্রশাসনিক তদন্তাধীন সদস্য।
4. **Archived (আর্কাইভকৃত):** সদস্যপদ চূড়ান্তভাবে ত্যাগকারী, বহিষ্কৃত বা প্রয়াত সদস্য (হিসাব নিষ্পত্তির জন্য স্থায়ীভাবে সংরক্ষিত)।

## ৪. সংবেদনশীল তথ্য ও গোপনীয়তা নিরাপত্তা (Privacy & Data Protection)

1. **জাতীয় পরিচয়পত্র (NID):** তালিকা স্ক্রিনে NID উন্মুক্ত নয়; কেবল পূর্ণ ভিউ পারমিশনপ্রাপ্ত ব্যবহারকারী প্রোফাইল প্যানেলে দেখতে পারেন।
2. **লগ ও অডিট সুরক্ষা:** অডিট লগে NID, ঠিকানা বা পাসওয়ার্ড প্লেনটেক্সট হিসেবে রাখা নিষিদ্ধ।
3. **কোনো আর্থিক লজিক নেই:** শেয়ার, সঞ্চয়, ডিপিএস বা ঋণ সংক্রান্ত কোনো আর্থিক লেনদেন Prompt 3.1-এ যুক্ত করা হয়নি (Scope Boundary সংরক্ষিত)।

## ৬. সদস্যপদ আবেদন ও অনুমোদন (Membership Application & Approval Workflow - Prompt 3.3)

```text
Application ≠ Member
Pending Application has zero financial impact.
```

1. **ডোমেন আইসোলেশন:** `MembershipApplication` এবং `Member` সম্পূর্ণ আলাদা সত্ত্বা। খসড়া, জমা বা পর্যালোচনাধীন কোনো আবেদন সাধারণ সদস্য হিসেবে গণ্য হবে না।
2. **আর্থিক প্রভাবহীনতা:** বিচারাধীন কোনো আবেদন শেয়ার, সঞ্চয়, ডিপিএস, ঋণ, চাঁদা, আয় বা সাধারণ লেজারে কোনো প্রকার ব্যালেন্স তৈরি করে না।
3. **অনুমোদনের পর সদস্য সৃষ্টি:** অনুমোদিত (`Approved`) হওয়ার পর স্বয়ংক্রিয়ভাবে একটি ইউনিক `MEM-XXXXXX` সদস্য রেকর্ড তৈরি হয় এবং তাদের মাঝে দ্বিমুখী রেফারেন্স আইডি সংরক্ষিত থাকে।
4. **দায়িত্ব বিভাজন (Separation of Duties):** আবেদন প্রস্তুতকারী কর্মকর্তা নিজে আবেদন অনুমোদন করতে পারবেন না (`creatorUserId != approverUserId`)।
5. **টার্মিনাল স্টেট প্রোটেকশন:** Approved, Rejected বা Withdrawn আবেদন থেকে কোনো ব্যাকওয়ার্ড ট্রানজিশন সম্ভব নয়।
